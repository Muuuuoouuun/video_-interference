# INTERFERENCE

영상의 **시점별 장면 내용과 피드백을 모아 전달하는** 1인용 로컬 웹앱 프로토타입입니다. 현재 시점이나 구간을 지정하고, 그림·참고 자료·피드백을 저장한 뒤 문서와 스틸 묶음으로 내보냅니다. 전달물에는 원본·편집 영상 파일을 넣지 않습니다. [현재 프로토타입 기획](docs/피드백프로토타입.md)을 기준으로 개발합니다.

**Premiere 연동 초안:** 더 보기 → Premiere 연동에서 영상·스틸 없는 연결 JSON, 투명 마크업 PNG 묶음, 개발용 UXP 패널을 받을 수 있습니다. 패널은 댓글을 마커로 갱신하고, 투명 PNG 오버레이를 댓글 IN–OUT에 맞춰 영상 위 전용 트랙에 배치합니다. 여러 그림 시점의 전환·겹침 합성과 동일 버전 재적용을 지원합니다. [설치·사용법과 현재 한계](integrations/premiere/README.md). 파일 기반 단방향 연동이며 실제 Premiere 호스트 검증은 아직 필요합니다.

제품의 우선순위는 **본질 → 편의성 → 사용성**입니다. 장면과 의도가 결과까지 정확히 이어지는 흐름을 먼저 완성합니다. [제품 판단·검수 기준](docs/제품원칙.md)을 따릅니다.

## 실행

Node.js 22.13 이상, FFmpeg, ffprobe가 필요합니다. 개발 환경은 Node.js 25.8.2와 macOS에서 검증했습니다.

```sh
npm install --bin-links=false
npm run dev
```

작업 폴더는 `/Volumes/OneTouch/video_interference`입니다. 데스크톱을 먼저 완성하고 모바일은 후속으로 다룹니다. 외장 디스크에서 심볼릭 링크를 요구하지 않도록 실행 스크립트를 구성했습니다.

브라우저에서 http://127.0.0.1:4317/ 을 엽니다. 워커는 127.0.0.1:4318에서 실행됩니다. 다른 사이트가 로컬 API를 호출하지 못하도록 Host와 Origin을 검사합니다.

선택적인 샘플은 `fixtures/demo.mp4`입니다. 샘플이 없으면 영상 열기 화면으로 시작합니다. 현재 로컬 초안의 샘플은 기존 ClassIn 작업 영상에서 가져왔으며 Git에는 포함하지 않습니다.

개인 영상·프로젝트 DB·검증 산출물과 원본 장면을 포함한 로컬 시안 이미지는 저장소에서 제외합니다. 문서의 `storage/qa/`·시안 이미지 경로는 로컬 개발 기록을 가리키므로 새로 복제한 저장소에는 해당 파일이 없습니다. 앱에 포함한 Pretendard 글꼴의 이용 조건은 [글꼴 라이선스](apps/web/public/fonts/LICENSE.txt)에 보관합니다.

## 기본 피드백 흐름

영상 열기 → 현재 시점 또는 선택 구간 → 장면 내용·피드백·그림 → 저장 → **피드백 내보내기** 순서입니다. 장면 설명은 선택 입력이며 사용자가 직접 작성합니다. 설명만 남기려면 메모로 저장합니다. 기본 저장은 AI 해석이나 렌더를 실행하지 않습니다.

전달 ZIP에는 `feedback.md`(사람용 문서), `feedback.jsonl`(한 줄에 피드백 하나인 AI·도구용 글), `feedback.vtt`(기준 버전 위에 띄우는 자막), `manifest.json`, 피드백별 한 장 요약, 영상 전체 흐름 이미지 1장, 관련 장면 스틸, 그림이 표시된 스틸과 첨부 자료를 담습니다. 그림 좌표는 `화면 왼쪽 위 · 가로 10–30%` 같은 위치 문장으로도 적습니다. 작성 버전의 시점과 현재 버전의 대응을 구분하며, 삭제된 장면의 피드백도 원래 스틸과 함께 보존합니다. 전체 문서는 텍스트로 복사할 수도 있습니다. 스틸·그림·첨부까지 전달하려면 ZIP을 사용합니다. 파일을 준비해도 외부로 자동 전송하지 않습니다.

시간축에는 각 버전의 실제 장면을 최대 12개 표시합니다. 펼친 타임라인에서 처음 필요할 때 준비하고 이후 캐시를 재사용합니다. 최소화 상태에서는 새 썸네일 요청을 미룹니다. **구간 반복**은 보기용이며, 켜는 것만으로 재생하지 않습니다. 구간 밖에서 재생하면 IN부터 시작하고 수동 탐색·그림 편집은 정지 상태를 유지합니다.

첨부 시안의 밝은 회색·흰 패널·파란 강조색을 적용했습니다. 왼쪽 프로젝트 패널은 기본으로 접고, 오른쪽 댓글 패널은 열어 둡니다. 양쪽 접기 버튼은 작성 내용을 유지합니다. 기본 입력은 타임코드·댓글·저장이며, 장면 설명·이미지·음성은 **추가 옵션**에서 선택합니다. 그림 도구는 바로 사용하고 색·굵기·채움은 **그림 스타일**을 펼쳐 조절합니다.

영상과 하단 타임라인 사이의 경계를 위아래로 끌어 높이를 조절합니다. **최소화**를 누르면 재생·현재 시각·탐색선·댓글 마커가 있는 48px 한 줄로 접혀 영상 공간이 커집니다. 펜 아이콘으로 그림 도구를 열고, 펼치기 버튼으로 이전 높이를 복원합니다. 모드와 높이는 이 브라우저에 저장합니다. 경계의 ↑↓/Shift는 작은·큰 조절, 더블클릭·Enter는 기본 높이 복원입니다.

앱 시작 시 첫 댓글과 예시 구간을 자동 선택하지 않습니다. 기본은 한 시점이며 **구간 지정** 또는 `I / O`로 범위를 만들고 **구간 해제 / ×**로 없앨 수 있습니다. 반복 재생도 구간 해제와 함께 꺼집니다.

목록에서 피드백·장면·추가 지시·첨부 이름을 검색하고 현재 영상 시간순이나 최근 작성순으로 검토합니다. 카드 번호는 타임라인과 유지됩니다. 저장 카드를 보다가 `C`를 누르면 현재 재생 시점에 작성하며, 작성 중인 초안이 있으면 해당 초안으로 복귀합니다. 저장 구간을 재사용하려면 카드 아래 **선택한 댓글 · 구간·마크업 재사용**을 펼쳐 **이 구간에 새 피드백**을 사용합니다.

첨부 이미지는 확대해서 좌우 방향키로 넘겨 봅니다. 저장 카드에서는 4장부터 보여 주고 음성은 항상 표시합니다. 첫 실행 화면은 영상 파일 하나를 끌어 놓거나 선택해서 시작할 수 있습니다.

## AI·도구로 받기

전달 자료는 **글을 먼저 읽고 이미지는 필요할 때만 여는** 순서로 구성합니다. `feedback.jsonl` 또는 `manifest.json` → 피드백별 한 장 요약(`sheets/`) → 개별 스틸(`scenes/`, `annotations/`) 순서이며, 영상 전체 흐름은 `overview/grid.jpg` 한 장과 자동 컷 구간 목록(추정)으로 봅니다. 형식은 [AI·도구용 전달 형식](docs/AI전달형식.md)과 [JSON Schema](schema/feedback-handoff.schema.json)에 정리했습니다.

앱 화면 없이도 받을 수 있습니다. 앱 DB를 읽기만 하며 모델 호출·외부 전송·받아쓰기는 하지 않습니다.

```sh
npm run export -- --format jsonl     # 한 줄에 피드백 하나를 표준 출력으로
npm run export -- --format md        # 사람용 문서
npm run export -- --format paths     # 생성된 파일 경로
```

음성 메모는 로컬 [whisper.cpp](https://github.com/ggml-org/whisper.cpp)를 설정하면 카드의 **로컬 받아쓰기**로 글로 바꿀 수 있습니다. 사용자가 누를 때만 실행하고, 자동 결과로 표시합니다. 설정은 `WHISPER_CPP_PATH`, `WHISPER_MODEL_PATH`(필수)와 `WHISPER_LANGUAGE`(기본 `ko`) 환경 변수로 워커를 시작할 때 지정합니다.

## 불러오기·내보내기 안정화 · 2026-10-28

- **영상 불러오기:** 첫 화면과 작업 화면 모두 ① 파일 받기 ② 검토용 영상 만들기 ③ 마무리 단계와 진행률·남은 시간을 보여 줍니다. **취소**하거나 창을 닫으면 변환을 멈추고 기존 프로젝트를 그대로 둡니다. 검토용 영상은 `superfast` 프리셋으로 만들어 같은 화질 기준(CRF 20)에서 변환이 약 1.4배 빠르고 파일은 커집니다. 작은 파일이 필요하면 `VI_PROXY_PRESET=veryfast`로 바꿉니다.
- **장면 전환 미리 계산:** 불러오기와 렌더가 이미 하는 디코딩에서 장면 점수를 함께 기록합니다. 처음 내보낼 때 영상 전체를 다시 디코딩하지 않습니다.
- **타임라인 썸네일·스틸:** 필요한 프레임 근처로 이동해 짧게 디코딩하는 묶음을 나누어 병렬로 처리합니다. 프레임 정확도 검사는 그대로 통과합니다. 한 번 뽑은 내보내기 스틸은 버전 파일별로 재사용합니다.
- **ZIP:** 외부 `/usr/bin/zip` 대신 내장 ZIP 작성기를 씁니다. 이미지·음성은 다시 압축하지 않고, 실패·취소 시 반쯤 만든 파일을 남기지 않으며, 4GB를 넘으면 ZIP64를 사용합니다.
- **이미지 첨부:** 선택한 순서를 유지하면서 3장씩 동시에 올립니다. 서버가 JSON이 아닌 오류를 돌려주거나 연결이 끊겨도 원인을 문장으로 보여 줍니다.
- **FFmpeg 경로:** `FFMPEG_PATH`가 없으면 `/opt/homebrew/bin` → `/usr/local/bin` → `PATH` 순서로 찾습니다.

4코어 Linux 컨테이너에서 5분 1080p 합성 영상·피드백 40개로 측정했습니다(`node scripts/benchmark-upload-export.mjs --video <파일>`). 불러오기 124초 → 약 104초, 타임라인 썸네일 59초 → 3초, 처음 내보내기 108초 → 11–14초, 피드백 하나 추가 후 다시 내보내기 약 2초입니다. 실제 영상과 PC 사양에 따라 달라지며 측정 결과는 `storage/qa/upload-export/`에 남습니다. [자세한 표](apps/worker/README.md#still-extraction-and-request-reliability).

## 부가 편집 기능과 기존 구현

상단 **더 보기 → 편집 기능**을 열면 명령 해석·승인·렌더와 레이어 수정이 나타납니다. 아래 편집 기능은 기본 피드백 전달에 필수인 단계가 아닙니다.

- 영상 가져오기와 실제 재생, IN/OUT 구간 선택
- 박스·원·선·화살표·펜에 각각 작성 프레임 저장, 장면별 표시·편집·선택·이동·크기·스타일과 되돌리기/다시 실행
- 명시적인 “영상에 넣기” 요청으로 그린 도형을 실제 MP4에 합성. 메모는 그대로 지시 자료로 보관
- 이미지 첨부의 참고/삽입 역할 선택, 영상 위 이미지 이동·크기 조절과 숫자 배치 저장
- 한국어 요청을 컷, 구간 유지, 배속, 자막, 텍스트·이미지·박스, 전체 오디오 음량 명령으로 해석
- 해석 값 수정, 승인과 승인 취소, 승인한 작업만 실행
- 적용된 자막·그래픽의 수정·제거 요청, 기존 레이어 순서·적용 구간과 이전 버전 보존
- 편집 요청과 메모 선택, 요청을 먼저 저장하고 카드에서 나중에 해석
- 같은 카드에 추가 지시 저장, 원문 보존과 명시적인 재해석. 보완 저장 시 이전 승인은 해제
- 저장된 위치 표시와 새 요청의 그림 구분, 장면 그룹을 명시적으로 골라 새 요청에 복사
- 컷·배속 뒤 기존 요청을 현재 버전의 대응 장면에 표시. 부분 생존·삭제·위치 확인 불가 상태 구분
- 작성 중인 요청·첨부·그림·범위 보존과 미저장 추가 지시 이어쓰기
- 렌더 취소, 상충하는 새 배속·삭제된 구간의 그래픽 요청 차단
- 실제 FFmpeg MP4 출력, 누적 편집 버전, 원본 위치를 기준으로 비교
- SQLite에 프로젝트·요청·버전 저장, 새 영상 가져오기 전 기존 프로젝트 JSON 보관
- 음성 지시 녹음과 파일 보관. 받아쓰기는 로컬 whisper.cpp를 설정했을 때 카드에서 직접 실행하며, 편집 명령 해석에는 쓰지 않아 지시 문구를 직접 입력

예시 요청은 `이 구간 삭제`, `이 구간만 남겨줘`, `2배속`, `자막: 배움이 이어지는 순간`, `음량 50%`, `무음`, `여기에 첨부한 이미지 넣어줘`, `메모: 타이틀 위치 검토`입니다. 메모는 실행하지 않습니다. 삽입 이미지는 첨부 역할을 영상에 삽입으로 선택해야 합니다.

한 장면의 도형은 **영상에 넣기 → 요청 카드의 승인 → 승인한 요청 실행** 순서로 반영합니다. 여러 장면에 그림을 남겼으면 요청으로 저장한 뒤, 넣을 장면의 그림 그룹을 골라 새 요청에 복사합니다. 서로 다른 장면의 그림을 한 화면에 자동으로 합성하지 않습니다. 이미지 요청의 **위치·크기**를 열면 영상 위에서 드래그와 모서리 조절이 가능하고, 숫자나 배치 프리셋으로도 저장할 수 있습니다. 위치를 바꾸면 승인이 해제됩니다.

편집본의 **적용된 자막·그래픽 → 수정 / 제거 요청 → 요청 카드 승인 → 승인한 요청 실행**으로 이미 넣은 그래픽을 변경합니다. 수정은 같은 레이어 자리를 교체하고 제거는 다음 버전에서만 제외합니다. 그림은 원본 장면 위에서 도형 도구로 수정하고, 자막·글자·박스의 색과 배치, 삽입 이미지도 바꿀 수 있습니다. 현재는 기존 종류와 적용 구간을 유지합니다. 그림 수정창은 해당 그래픽만 보여 주며 다른 레이어를 포함한 합성 결과는 렌더 후 확인합니다. 이미지 교체의 위치는 숫자로 수정하며 기존 합성 이미지 위에 교체안을 중복 표시하지 않습니다. 수정창을 여는 동안 작성 중인 새 요청의 장면·내용을 보존합니다.

일반 요청은 먼저 저장한 뒤 카드의 **요청 해석**으로 처리할 수 있습니다. **저장 후 바로 해석**을 선택하면 저장과 해석을 이어서 실행합니다. 원문 저장 뒤 해석이 실패해도 같은 카드에서 다시 시도합니다. 메모는 별도로 저장하며 편집 명령으로 해석하지 않습니다. 음성만 저장하는 것도 가능하고, 녹음 당시의 구간·각 그림 프레임이 함께 고정됩니다. 음성 첨부가 있는 동안 구간·그림을 수정하려면 음성 첨부를 먼저 제거합니다. 녹음 파일 저장에 실패하면 같은 음성과 당시 시점·그림을 유지하며 **다시 저장 / 이번 녹음 버리기**를 제공합니다. 새 녹음 저장이 성공할 때만 기존 음성을 교체합니다. 실패한 녹음은 현재 화면의 메모리에 보관하며 새로고침·앱 종료 뒤 복구를 지원하지 않습니다.

요청 카드와 시간축은 현재 버전의 대응 구간을 보여 줍니다. 카드를 선택해도 현재 버전을 유지하며, **작성 버전 보기**는 원래 장면을 확인하는 별도 행동입니다. 삭제된 대상은 가까운 다른 장면으로 옮기지 않습니다. 여러 구간으로 나뉜 요청은 구간 하나를 선택해 새 요청을 남깁니다. 해석·승인은 요청의 작성 버전을 기준으로 유지합니다.

저장 구간을 명시적으로 재사용한 새 요청은 해당 구간 안에서 시작합니다. 그림 복사는 **장면 시각 · 그림 개수**로 표시한 그룹을 명시적으로 선택하며 해당 그림 프레임을 유지합니다. 선택 구간 밖이면 참고 장면이라는 표시를 보여 줍니다. 그림을 그린 장면이 삭제됐으면 숨기고 삭제 개수를 표시하며 다른 장면으로 옮겨 복사하지 않습니다. 프레임 정보가 없는 기존 그림은 원래 댓글의 기준 프레임을 사용합니다.

기존 요청을 확인하는 동안 새 요청의 초안은 유지됩니다. 저장된 그림은 읽기 전용이고 원래 작성 프레임의 대응 위치에서만 표시합니다. 작성 중인 요청이 있으면 버전 교체·새 영상 가져오기를 막습니다. 카드에 쓰던 추가 지시도 저장·취소 전에는 새 영상을 가져올 수 없고, **작성 중인 보완 · 이어쓰기**로 돌아갈 수 있습니다.

그림 도구는 `V` 선택, `B` 박스, `E` 원, `L` 선, `A` 화살표, `P` 펜을 사용합니다. 장면 버튼으로 그림이 있는 프레임을 열고 현재 프레임의 그림만 편집합니다. **현재 프레임 그림 지우기**는 다른 프레임의 그림을 보존합니다. 방향키는 선택한 그림을 1px 이동하고 Shift와 함께 누르면 10px 이동합니다. Escape는 선택 해제, Delete는 선택 삭제, ⌘/Ctrl Z는 전체 요청의 그림 기록 되돌리기입니다. 한 요청 전체에 그림 30개, 펜 하나에 최대 2,000점, 기록 50단계를 유지합니다. 프레임 이동과 저장 카드 검토 후 초안 복귀에도 undo/redo 기록을 유지합니다. 방향키를 길게 누른 한 번의 이동은 한 단계로 되돌립니다. Tab으로 다른 영역에 이동하면 그림 단축키가 그 영역의 입력을 가로채지 않습니다. 요청 저장·다른 버전/영상 열기·새 초안 생성은 새 기록으로 시작합니다. 기록은 실행 중인 초안의 메모리에 보관하며 앱 재시작 복구를 뜻하지 않습니다.

요청 수정 후 승인은 해제됩니다. 렌더 완료는 자동 채택이 아니며 버전 목록에서 결과를 선택해 확인합니다. 이전 렌더를 반복 인코딩하지 않고 보존된 원본과 불변 편집 스냅샷으로 재생성합니다. MP4 인코딩 자체는 무손실이 아닙니다.

## 해석 모드

사용자 결정에 따라 필요한 AI API 테스트에는 **Gemini**를 사용합니다. `npm run test:gemini -- /path/to/manifest.json`은 로컬 검증만 하고, `--live`를 붙일 때 선택한 피드백·스틸·그림·참고 이미지를 한 번 전송합니다. 키는 Git에서 제외된 `.env.local`에 둡니다. PC 영상의 피드백 3개·이미지 16개로 실제 Gemini 호출 1회를 완료했고, 원문·보완 내용과 삭제 상태를 대조했습니다. 영상·음성 파일은 보내지 않고, 앱의 원문·시점·승인·버전은 유지합니다. [Gemini 테스트 사용법과 검수 기준](docs/Gemini테스트.md).

기본은 **로컬 규칙 해석**입니다. 화면에 `AI API 미연결`이라고 표시합니다. AI의 의미 이해와 스타일 복제를 구현했다고 주장하지 않습니다. 음성 받아쓰기는 사용자가 설정한 로컬 whisper.cpp 결과이며, 이 저장소의 자동 검사는 실제 음성 인식 품질을 검증하지 않았습니다.

선택적인 Claude 어댑터는 워커 프로세스에 `ANTHROPIC_API_KEY`와 `ANTHROPIC_MODEL`을 모두 설정한 경우 활성화됩니다. 키는 브라우저에 보내지 않습니다. 이 모드는 선택 프레임, 요청, 드로잉 좌표와 첨부 이미지를 API에 전달합니다. 실제 Claude 호출은 이번 검증에 포함하지 않았습니다.

기본 앱의 그림별 장면 자료 기능은 **로컬 자료 준비**입니다. Gemini 호출은 위의 명시적 테스트 경로에서만 진행합니다. 요청 카드의 **AI용 자료 준비**를 누르면 원문·보완 이력·그림 좌표·그림별 장면과 구간 시작·중간·끝 스틸·그림 표시 스틸·한 장 요약·첨부 이미지·음성 원본을 로컬 묶음으로 준비합니다. manifest는 피드백 내보내기와 같은 항목 형식(`feedback[0]`)을 함께 담습니다. **자료 묶음 받기**에서 ZIP을, **자료 목록**에서 manifest를 열 수 있습니다. 추가 지시를 작성 중이면 먼저 저장합니다. 그래픽 변경 요청은 변경 대상의 불변 스냅샷과 현재 수정안도 함께 저장합니다. 저장 후 값을 바꾸면 이전 자료 링크를 숨기고 다시 준비할 수 있습니다. 모델을 호출하거나 외부로 전송하지 않습니다. 기존 외부 어댑터를 여러 장면 자료 전송으로 확장하지 않았고, 프레임이 지정된 그림 요청은 실제 외부 AI 해석을 호출했다고 표시하지 않습니다.

## 제한과 다음 개발

초안은 단일 원본, SDR, 10분 이하, 최대 2GB를 지원하며 검수 프록시와 결과는 30fps CFR로 처리합니다. 원본 VFR의 엄밀한 PTS 대응과 브라우저 프레임 정확도는 후속 검증이 필요합니다. 타임라인은 해당 버전의 실제 장면을 최대 12개 보여 줍니다. 확대 탐색과 더 촘촘한 썸네일은 후속입니다.

피드백 프로토타입 이후의 전체 편집 제품에는 실제 AI 의미 해석·받아쓰기의 편집 명령 연결, 원본 PTS와 프록시 매핑·표시 프레임 확정, 요청 revision·계획 이력, 그래픽 출력 길이 정책, 보관 프로젝트 복원이 남아 있습니다. 그림별 프레임 저장과 이번 투영은 30fps CFR 기준이며 원본 VFR의 정밀 PTS 앵커까지 완성한 기능이 아닙니다. [완료 항목과 남은 조건](docs/완료감사.md)을 유지합니다.

움직이는 물체 추적, 줌, 장면 재생성, 기존 영상에 구워진 자막 제거, 배경음과 음성 분리, 외부 공유와 NLE 연동은 후속 범위입니다.

다음 검수는 시점·장면 내용·피드백이 저장과 내보내기까지 이어지는지, 초안 복귀와 그림 조작이 편한지 확인하는 것입니다. 실제 AI 해석, 받아쓰기의 편집 명령 연결, 정밀 원본 앵커는 후속 편집 제품 계획으로 보존하며 공급자 설정을 피드백 저장의 선행 조건으로 만들지 않습니다.

디자인 토큰·공용 컴포넌트·렌더 속도·작성창 위치 등 화면 개선의 순서와 목표 지표는 [화면 개선 기획](docs/화면개선기획.md)에 정리했습니다. 피드백 150개 기준의 실제 브라우저 측정값을 근거로 합니다.

요청 투영 검사는 컷·배속 후 대응 프레임, 삭제된 대상, 분리 구간의 원본 버전 회귀, 범위와 독립된 그림 프레임, 배속 반올림과 동일 버전의 선택 범위 보존을 확인합니다. native 검사에서는 투영 위치의 실제 출력 색상 마커를 읽습니다. 새 요청 생성은 선택 구간 하나만 사용하고 그림 복사는 원래 요청을 변경하지 않는지도 검사합니다.

PC 영상 호환성·성능 측정은 `node scripts/benchmark-real-media.mjs --help`로 확인합니다. 개인 영상과 생성된 검증 결과는 `storage/qa/`에만 저장합니다. 실제 원본 검사와 파생 호환성 샘플은 구분하며, 측정치는 해당 PC의 샘플 결과입니다. 그림 이동·크기 조절은 포인터의 최신 위치를 모아 RAF마다 한 번 계산하고, 놓는 순간 마지막 위치를 즉시 확정합니다. 기존 펜을 선택·이동·크기 조절할 때는 점을 다시 단순화하지 않아 작은 비교 화면에서도 선을 보존합니다. 렌더는 같은 시간 범위의 그래픽을 합성하고 내용 기준 PNG 캐시를 사용합니다.

그림 기록 검사 13개는 초안별 undo/redo, 외부 교체, 50단계 제한, 불변 좌표 공유를 확인합니다. `node scripts/benchmark-drawing-history.mjs`는 30펜×2,000점에서 이전 키 이동 경로와 새 그룹 기록의 순수 상태 처리 비용을 비교합니다. 전체 앱 렌더나 브라우저 입력 지연의 측정이 아닙니다.

레이어 변경은 순수 검사 6개와 native 검사 2개, API 시나리오 1개를 추가했습니다. PC의 35초 원본 중 6초로 만든 버전 4개에서는 위치·색·이미지 제거·겹침 순서·반열림 노출 경계·옛 버전 분기를 14개 픽셀 조건으로 확인했고 원본과 이전 결과 해시를 보존했습니다. [실제 결과와 검증 보고서](storage/qa/layer-revisions/report.json)를 남겼습니다.

피드백 전달 검사는 장면 설명·원문·보완·작성 시점과 현재 대응·삭제 상태·그림 스틸·공유 첨부를 대조합니다. ZIP을 풀어 상대 경로와 파일 해시를 확인하며 영상 파일과 외부 전송이 없는지 검사합니다. [PC 피드백 전달 보고서](storage/qa/feedback-export/report.json)를 보관합니다. 썸네일 검사는 원본·편집본 24개 셀을 독립 추출과 비교했고 오차가 0이었습니다.

펜 동작 회귀 검사 8개와 음성 재시도 검사 4개를 추가했습니다. PC 영상 스틸 위의 선택·이동·크기 조절 결과를 독립 기대 좌표로 그린 그림과 비교해 픽셀 차이 0을 확인했습니다. [펜 보존·계산 비용 검증](storage/qa/overlay-gesture/report.json)은 순수 좌표 처리와 스틸 합성의 결과이며 실제 브라우저 입력 속도 측정이 아닙니다.

화살표 머리·굵은 선·펜 점의 선택 영역은 실제 컴포넌트의 SVG 출력으로 검사합니다. 400·1000·1600px 화면 폭에서 보이는 그림을 포함하고 최소 14px 선택 폭을 유지합니다. 창 크기와 캔버스 조상 스크롤이 바뀌면 진행 중 드래그를 취소해 이전 화면 좌표로 저장하지 않습니다.

현재 자동 검사는 실제 데스크톱 화면 조작 검수를 대신하지 않습니다. 저장된 브라우저 권한 차단 때문에 새 입력·투영·초안 복귀의 화면 검수는 완료하지 못했습니다. 검사 결과와 한계는 [오버레이·PC 영상 검증](docs/오버레이검증.md)에 기록합니다.

