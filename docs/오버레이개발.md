# 그림·도형 오버레이 개발 기록

2026년 10월 14일 · `/Volumes/OneTouch/video_interference` · 데스크톱 우선

이번 개발은 PC의 실제 영상으로 편집 엔진을 검증하고, 그림·도형의 편집과 출력 경로를 확장하는 데 집중했다. 모바일은 후속으로 둔다. 첫 사용자는 혼자 영상을 제작하는 사용자이며, 승인된 명령만 새 버전에 반영한다.

## 사용 흐름

1. 영상을 열고 IN/OUT으로 요청 구간을 잡는다.
2. 정지 화면에서 박스, 원, 선, 화살표 또는 펜을 선택해 그린다.
3. 선택 도구로 이동하고 핸들로 크기를 조절한다. 선 색상·두께·불투명도, 닫힌 도형의 채움을 바꿀 수 있다.
4. 위치 설명용 그림은 요청과 함께 메모로 저장한다. 실제 그래픽으로 쓰려면 **영상에 넣기**를 누른다.
5. 요청 카드에서 도형 수와 구간을 확인하고 승인한 뒤 렌더한다.
6. 새 버전을 선택해 비교하거나 MP4로 다운로드한다.

이미지는 첨부 전에 역할을 **영상에 삽입**으로 선택하고 이미지 삽입 요청을 작성한다. 요청 카드의 **위치·크기**를 열면 영상 위에서 이동·크기 조절을 할 수 있다. 숫자나 오른쪽 위·가운데·아래쪽 프리셋을 저장할 수도 있다. 이미지 원본 비율과 알파 채널을 유지하며, 위치가 바뀌면 승인이 해제된다.

## 입력과 렌더 계약

| 항목 | 규칙 |
|---|---|
| 시간 | 30fps 프레임, `[frameIn, frameOut)` |
| 좌표 | 실제 영상 표시 영역에 대한 0~1 비율. 레터박스 여백 제외 |
| 선 굵기 | 영상 너비 1000의 논리 단위. 화면과 출력에서 같은 비율로 확대 |
| 투명도 | 0~1, 도형 전체에 적용 |
| 채움 | 사각형·타원에만 적용. 열린 선·펜의 내부는 채우지 않음 |
| 화살표 | 화면과 렌더가 같은 삼각형 머리 공식 사용 |
| 출력 명령 | `overlay`, `params.kind='drawing'`, 검증된 `params.drawings` |
| 편집 기록 | 최대 50단계, 요청 또는 버전 맥락이 바뀌면 초기화 |
| 입력 제한 | 요청당 30개, 펜당 2,000점 |

사용자의 그림, 참고 이미지와 음성 메모는 자동으로 출력하지 않는다. “영상에 넣기”는 해석 제안을 만들며, 실행 승인은 요청 카드에서 따로 한다. 기본 해석은 로컬 규칙이고 실제 AI 호출이나 자동 받아쓰기를 완료했다고 표시하지 않는다.

## 최적화

포인터 이동 중에는 독립 `OverlayEditor`의 미리보기만 RAF로 갱신한다. 펜은 브라우저의 coalesced points를 읽고 가까운 점을 줄인다. 이미 확정된 도형은 memo 처리하고, 포인터가 끝났을 때 전체 그림 목록을 한 번 확정한다. 오래 그린 펜의 점 개수와 편집 기록 수에 상한을 둔다.

요청 목록은 댓글별 명령 맵을 재사용하고 영상 재생 중 불필요한 갱신을 줄인다. 그림 편집과 플레이어 단축키는 입력 영역과 선택 상태를 기준으로 분리한다.

렌더 시간축은 컷·유지·배속·음량 변경 지점으로 나눈다. 자막과 오버레이 시작·끝은 시간축 분할을 만들지 않고 출력 시간에 합성한다. 같은 시간 범위에 있는 연속 그래픽은 하나의 PNG로 합성하며, 중간 레이어를 건너뛰어 합치지 않아 겹침 순서를 보존한다. 그래픽 내용·영상 크기·에셋 정보에 따른 PNG 캐시로 반복 렌더의 래스터 작업을 줄인다.

## 검증과 남은 확인

네이티브 FFmpeg 테스트는 실제 픽셀, 알파, 반영 구간, 컷·배속 뒤 시간 매핑, 이미지 이동, 도형 스타일, 승인과 스냅샷 보존을 검사한다. PC 영상 테스트는 실제 원본과 파생 호환성 샘플을 구분하며 원본 해시를 비교한다. 무음 파일 출력에서 발견된 DC 신호는 부동소수점 오디오 형식으로 통일해 수정했다.

실제 브라우저의 새 드래그·핸들 조작과 입력 지연 검증은 아직 완료되지 않았다. 사용자가 접근을 허용하고 설정을 변경했지만 브라우저 도구가 계속 저장된 사이트 차단 사유를 반환했다. 브라우저 성능 수치를 렌더 성능 수치로 대신 주장하지 않는다. 기존 초안의 화면 검증 기록과 이번 변경의 상태를 구분한다.

최종 측정 및 실행 결과는 [오버레이검증.md](오버레이검증.md)에 기록한다.

### UI 소스 검증 범위

`overlay-geometry.test.mjs`의 12개 검사는 역방향 드래그, 화면 밖 이동 제한, 모서리·끝점 크기 조절, 펜 경로 비율 변환, 작은 새 도형 제외와 의도적인 펜 점 허용, 2,000점 제한, 네이티브 렌더와 같은 화살표 머리, 스타일 범위, region만 있는 기존 도형의 보존과 이동·크기 조절을 확인한다. region과 points가 다른 기존 사각형·타원은 렌더와 같이 region을 기준으로 편집한다. 너비 1000의 논리 좌표와 실제 영상 표시 비율을 함께 사용하며 그림은 영상 영역에 잘리고 편집 핸들은 영역 밖에서도 잡을 수 있다.

UI 빌드와 TypeScript 검사는 통과했다. 코드는 포인터 이동 중 부모 `VideoWorkspace`의 그림 목록을 변경하지 않고 RAF 미리보기를 독립 컴포넌트에서 갱신한다. 확정 도형은 memo로 유지하며, 스타일 슬라이더는 한 번의 조작을 하나의 기록으로 묶고 다른 작업으로 넘어가기 전에 기록을 확정한다. 이 항목은 소스와 순수 계산 검증 결과다. 실제 브라우저의 드래그 감촉, 색상 선택창, 키보드·포커스, 손떨림 입력과 입력 지연 수치를 측정한 결과는 포함하지 않는다.

### 후속 안정성 보완

요청 카드를 선택하면 재생을 정지하고 해당 맥락 프레임으로 이동한다. 펜 클릭은 점으로 저장하며, 점은 직접 이동하고 선 굵기로 크기를 바꾼다. 시간축과 이미지 배치는 포인터 ID를 확인하고 캡처가 유실되면 조작을 정리한다. 이미지 배치 테두리는 실제 이미지 영역의 크기를 줄이지 않도록 outline으로 표시한다.

녹음은 시작 시점의 구간·프레임·그림을 함께 고정한다. 마이크 권한 응답이 작성창 종료 뒤에 도착하면 즉시 모든 트랙을 닫는다. 이미지 업로드·녹음·해석 중 새 영상이나 버전으로 바뀌어 요청 맥락이 섞이는 경로를 보호한다.

사용자 지시에 따라 요청은 먼저 저장하고 나중에 해석할 수 있다. 작성창에서 편집 요청과 메모를 명시적으로 고르며, 메모는 실행 명령으로 해석하지 않는다. 즉시 해석을 선택한 경우에도 원문 저장에 성공하고 해석만 실패하면 저장된 카드에서 다시 시도한다.

제품의 우선순위는 [본질 → 편의성 → 사용성](제품원칙.md)이다. 저장된 요청의 문장·그림·구간은 유지하고, 추가 지시를 같은 카드에 기록한다. 보완 저장은 이전 제안과 승인을 무효화하며 재해석은 별도 동작이다. 로컬 규칙에서 충돌한 배속·자막은 임의 선택하지 않는다. 마지막 보완에 “최종 3배속” 또는 “최종 자막: 문구”처럼 명시하면 해당 값만 확정할 수 있다.

저장된 위치 표시는 작성 프레임에서 읽기 전용으로 보여준다. 새 요청의 그림과 범위는 별도 초안에 유지하며, 저장된 그림을 가져가려면 “그림 복사해 새 요청”을 사용한다. 기존 요청을 살펴보는 동안 같은 버전의 작성 중인 초안은 유지한다. 초안이 있으면 버전·영상 변경을 잠가 맥락을 잃지 않게 한다. 현재 이 초안 보존은 열린 앱의 메모리 안에서 동작하며 새로고침 후 초안 복구를 구현한 것은 아니다.

녹음 중 요청 마커 선택을 막고 저장 중 문장·첨부·그림·구간을 잠근다. 서버가 저장 성공을 응답한 뒤 상태 조회만 실패하면 저장 성공을 유지하고 “다시 연결”을 안내한다. 이 화면 흐름은 소스 검토·TypeScript·빌드로 확인했고, 실제 브라우저 검수는 남아 있다.
