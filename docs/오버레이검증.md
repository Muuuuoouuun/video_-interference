## 영상 높이 조절·48px 집중 모드

영상과 하단 패널 사이에 높이 조절 경계를 추가하고, 남은 공간을 미리보기가 채우도록 고정 최대 높이를 해제했다. 타임라인 최소화는 재생·시간·탐색선·마커·그림 도구·댓글·펼치기를 48px 한 줄에 배치한다. 펼치면 저장한 높이로 복원하며 영상 요소와 그림 편집기는 유지한다. 마커 목록은 스크롤 영역 밖에 표시해 하단 패널 경계에서 잘리지 않도록 했다.

높이 계산 7개와 실제 컴포넌트의 SSR 3개를 추가했다. 임시 축소와 선호 높이 구분, 드래그 방향·제한·원점 복귀, 매우 낮은 창의 제어 영역, 저장 실패 복구, 집중 모드에서도 남는 탐색·마커·구간 손잡이·펼치기를 확인한다. 최종 전체 검사 **251/251, 실패·생략 0**, TypeScript·Vite 빌드 성공. [검사 로그](/tmp/video-interference-final-stability-tests.log)와 [빌드 로그](/tmp/video-interference-final-stability-build.log)는 이번 세션의 임시 파일이다. JS 435.69kB(gzip 135.91kB), CSS 127.26kB(gzip 23.30kB)다.

후속 안정화에서 IN/OUT 드래그의 여러 포인터 입력을 화면 갱신 주기로 묶고, 마지막 위치·1프레임 최소 구간·끝 경계·원점 복귀·중복 갱신 억제의 계산 검사 3개를 추가했다. 버전 전환 뒤에도 새 시간축의 크기·스크롤 변경을 감시한다. 집중 모드에서는 썸네일 요청을 미루고 완료한 결과를 재사용하며, 다른 마커 선택 시 목록 닫기와 컴팩트 마커 스타일 충돌을 수정했다. 이 계산 검사는 실제 포인터 지연 측정이 아니다.

실제 브라우저에서 높이 드래그·모드 전환·팝업·포커스·그림 조작은 도구의 기존 접근 제한으로 실행하지 못했다. CSS·상태 계산·SSR 검사를 화면 검수나 입력 속도 측정으로 계산하지 않는다.

## 시간축 탐색·패널 조절

시간 눈금·마커 주변 빈 공간·필름스트립을 같은 탐색 영역으로 연결했다. 클릭·드래그로 재생 위치를 옮기고, hover는 이동할 타임코드만 표시한다. 마커·IN/OUT 손잡이·팝업은 각자의 조작을 유지한다. 눈금에 키보드 초점이 있을 때 방향키는 1프레임, Shift+방향키는 1초, PageUp/Down은 5초, Home/End는 처음/마지막 재생 프레임으로 이동한다. 좌표 환산·끝 경계·긴 영상의 순수 계산과 실제 컴포넌트의 SSR 접근성 구조를 검사했다. 포인터 이벤트와 영상 seek의 실제 화면 연결은 미검증이다.

양쪽 패널은 경계 드래그·방향키로 너비를 조절하고 더블클릭·Enter로 기본 너비를 복원한다. 화면 폭에 따른 임시 축소와 저장한 선호 너비를 구분하며, 조절 중에는 프레임당 한 번 계산하고 확정 시에만 저장한다. 폭 계산·축소 상태에서 드래그 시작·접힘·저장값 복원의 자동 검사를 통과했다. 실제 영상·댓글을 함께 표시한 상태의 반응 속도는 측정하지 못했다.

## 수평·수직 펜의 크기 조절

수평 펜의 오른쪽에 3개 손잡이가 겹쳐 마지막 모서리 손잡이가 선택되던 경로를 재현했다. 1000×500 화면에서 수평으로 늘려도 최소 높이 보정이 적용돼 선이 아래로 1.5px 이동했다. 화면상 높이 3px 이하인 펜에는 좌우, 폭 3px 이하에는 상하 손잡이만 표시하도록 고쳤다. 두 축 모두 3px 이하이면 이동만 제공한다.

조절하지 않는 축은 원래 좌표를 직접 유지해 미세한 굴곡도 보존한다. 5개 회귀 검사에서 수평·수직·얇은 굴곡, 여러 화면 크기와 3px 경계, 손잡이를 비껴 잡은 위치, 반대 축으로 흔들린 포인터, 기존 박스·원의 최소 크기와 선·화살표의 끝점 동작을 확인했다. 이는 실제 사용 함수의 좌표 검사이며 SVG 포인터 이벤트나 체감 속도 검증은 아니다.

## 앞선 2026-10-15 사용성·성능 점검

크기 조절 손잡이의 중심과 실제 잡은 지점의 차이를 무시하던 문제를 수정했다. 예를 들어 오른쪽 경계가 600px인 도형을 592px에서 잡고 오른쪽으로 1px 움직이면, 기존 계산은 경계를 593px로 옮겼다. 새 계산은 처음 잡은 위치를 유지하며 경계를 601px로 옮긴다. 사각형·타원 8개 손잡이, 선·화살표 양 끝, 펜 정점 보존, 최소 크기·화면 경계, 원래 위치로 복귀 시 undo/redo 유지에 대한 회귀 검사 4개를 추가했다. 이는 제스처 계산 검증이며 실제 포인터 조작 검증은 아니다.

[PC 프레임 합성 보고서](../storage/qa/resize-grab-2026-10-15/report.json)에서는 1920×1080 원본의 75프레임에 수정된 사각형·타원·화살표·펜을 합성했다. 앱의 변형 함수를 사용하지 않고 직접 작성한 기대 좌표와 비교해 네 경우 모두 픽셀 차이 0이었다. 이전 raw-pointer 계산은 각각 5,234·15,752·5,916·6,638픽셀이 달라 결함을 구별하는 자료임을 확인했다. 원본 SHA256·크기·수정 시각은 유지했고 외부 전송은 없었다. 이 역시 브라우저 이벤트·포커스·입력 지연의 증거는 아니다.

우측 댓글 패널의 단일 헤더, 아이콘·개수를 함께 보여 주는 필터, 전체 폭 검색창과 별도 정렬·이동 행을 유지했다. 기본 댓글·작성창·타임코드 흐름의 소스 감사에서 추가 P1/P2를 발견하지 못했다. 선택적 편집 기능에는 미저장 보완·댓글 수정 중 이미지 배치를 계속 저장할 수 있는 잠금 누락이 있었다. 미리보기의 편집 가능 여부와 저장 콜백 양쪽에서 해당 초안을 확인하도록 수정했다. 보완 저장 시 기존 명령이 무효화되어 새 위치 변경을 잃는 경로를 막는다. 이 항목은 코드 검토·빌드 수준이며 실제 화면 조작 검증은 아니다. 좁은 패널에서 개수 표시·줄바꿈, 초안 복귀와 현재 영상 위치, 입력 반응 속도의 실제 화면 검수가 남는다.

| 투영 장면 native 확인 | 통과 | 6초 합성 영상의 컷·배속 출력에서 대응 프레임의 실제 색상 마커 확인. 삭제 context는 null 유지 |
| 선택 구간의 새 요청 | 통과 | 분리 범위 하나만 선택, 일반 요청은 그 범위 안에서 시작, 명시적 그림 복사는 원래 context와 복사본 유지, 삭제된 그림 context 복사 차단 |

영상·음성 프레임 경계 검증은 FFmpeg 출력 파일을 읽어 확인했다. Claude 이력 전달의 API 검사는 외부 네트워크를 차단한 stub이며 실제 모델 호출이 아니다. Claude 실제 호출과 자동 음성 전사는 이번 검사에 포함하지 않았다. 저장된 그림과 새 초안의 분리·녹음/저장 중 조작 잠금은 소스 검토와 빌드로 확인했으며 실제 화면 조작 통과로 계산하지 않았다.

앞선 113개 검사 단계는 Composer의 음성 앵커 잠금과 재녹음 실패 보완을 포함한다. 새 음성 업로드가 성공할 때만 첨부와 녹음 앵커를 함께 교체하며 실패하면 이전 음성과 앵커를 유지한다. 이는 소스·build 확인이며 실제 마이크나 업로드 실패 화면 검증의 통과 기록은 아니다.

## 펜 모양 보존과 음성 실패 복구

펜 그림의 완료 처리에서 모든 조작에 점 단순화를 다시 적용하던 오류를 수정했다. 1000×562.5 화면에서 만든 202점의 선을 500×281.25 화면에서 클릭만 해도 기존 경로는 2점으로 줄었다. 새 경로는 선택·이동·네 모서리 크기 조절에서 202점을 유지한다. 새로 그리는 펜만 완료 시 단순화하고, 입력을 모아 처리할 때 놓는 순간의 마지막 좌표와 이전 미리보기의 불변성을 보존한다.

[독립 재현 보고서](../storage/qa/overlay-gesture/report.json)는 PC의 35초 ClassIn 영상 75프레임을 추출해 합성했다. 기존 선택 동작은 원래 그림과 6,218픽셀이 달라졌고, 수정 후 선택·이동·크기 조절은 각각 독립 기대 결과와 차이 0이었다. 원본 영상 SHA256도 유지했다. 취소 검사는 helper를 버렸을 때 원본이 변하지 않는지와 UI의 RAF 취소 연결을 확인한 것이며 브라우저 pointercancel 이벤트를 실행한 검사가 아니다.

2,000점 펜·7,200개 포인터 위치를 600번의 수동 화면 갱신 묶음으로 처리한 Node 계산 비교에서 이동 중앙값은 215.80→22.40ms, 크기 조절은 233.77→24.67ms였다. 워밍업 후 이전/새 경로를 5회씩 측정했고 최종 좌표도 같았다. 실제 RAF·렌더·입력 지연·FPS를 측정하지 않았으며 메모리 사용 감소의 근거로 삼지 않는다. IN/OUT 손잡이의 이동 이벤트가 부모까지 중복 전달되던 코드 경로도 한 번만 처리하도록 보완했다. 이 이벤트 수정은 소스 검토 수준이다.

음성 업로드가 실패하면 Blob·파일명·녹음 당시 범위와 그림을 메모리에 보관하고 다시 저장하거나 명시적으로 버릴 수 있다. 기존 음성은 새 업로드 성공 시에만 교체한다. 4개 상태 검사에서 정확히 같은 파일과 앵커 재시도, 중복 시도 차단, 늦은 응답 무시, 이전 첨부 보존을 확인했다. Composer의 제출·새 녹음·앵커 잠금 연결은 소스·TypeScript 빌드로 확인했다. 실제 마이크·실패 안내 클릭·새로고침 복구는 검증 범위에 포함하지 않는다.

## 요청 투영과 초안 보존

`comment-projection`은 불변 원본 범위를 현재 버전의 30fps 시간축에 대응시킨다. 범위와 그림 작성 프레임은 따로 계산한다. 완전히 삭제된 요청은 가까운 장면에 붙이지 않으며, 그림 프레임만 삭제된 경우에는 살아 있는 요청 구간을 검수하되 해당 그림의 표시·복사를 막는다. 다른 프레임의 살아 있는 그림 그룹은 별도로 유지한다. 배속 반올림으로 출력 폭이 0이 된 범위는 실제 삭제와 구분한다. 분리 범위는 원본과 출력 모두 이어질 때만 합쳐 컷 사이의 장면을 요청에 섞지 않는다.

UI 소스는 현재 버전을 유지하는 카드 선택, 현재 위치와 작성 버전의 별도 표시, 분리 구간 선택, 명시적 작성 버전 열기를 연결한다. 일반 새 요청은 선택 구간 안에서 시작한다. 그림 복사는 원래 그림 context를 보존하고, 선택 구간 밖이면 기준 시각과 보존 사실을 저장 화면에 표시한다. 원래 댓글과 그림은 변경하지 않는다. 같은 버전에서는 저장된 요청을 확인해도 Composer를 유지해 문장·첨부·그림·범위의 초안을 보존한다. 미저장 보완 문장도 이어쓰기 대상이며 저장·취소 전 새 영상 가져오기를 차단한다.

[현재 프로젝트 읽기 기록](../storage/qa/request-projection/live-readback.json)은 API의 저장 상태와 순수 계산을 대조한 증거다. v1 514프레임·v2 454프레임에서 기존 범위 150–270은 150–210으로, 270–360은 210–300으로 대응했다. 이는 브라우저 클릭·시킹·그림 복사 동작의 증거가 아니다. 이번 투영은 canonical CFR 계산으로서 원본 VFR PTS 인덱스·클립 인스턴스·실제 브라우저 표시 프레임의 정밀 확인을 완료한 기능으로 계산하지 않는다.

## 프레임별 그림과 로컬 자료 준비

`Drawing.frame`은 각 그림의 작성 프레임을 보존한다. 기존 데이터는 댓글의 기준 프레임을 사용한다. 현재 프레임만 편집·지우고 장면 버튼으로 이동한다. 프레임 이동 중 드래그는 취소하며 전체 그림 이력은 유지한다. 카드 검토 후 초안 복귀에도 undo/redo를 보존한다. 새 초안·다른 버전·다른 영상으로 전환하면 별도 기록을 사용한다. 앱 재시작 뒤 초안 기록 복구는 지원하지 않는다. 장면별 명시적 복사와 삭제/위치 확인 불가 개수를 표시한다. 여러 장면의 그림을 하나의 정적 그래픽으로 자동 합치거나 지역 자막·오버레이에 첫 위치를 임의로 선택하지 않는다.

사용자 결정에 따라 현재 AI 작업은 로컬 자료 준비까지다. 편집 기능 안에 남겨 둔 개별 **AI용 자료 준비**는 원문·보완 이력·그림 좌표·관련 스틸·첨부 이미지·음성 원본을 묶는다. 아직 저장하지 않은 추가 지시가 있으면 먼저 저장하도록 한다. 30개 그림 장면과 요청 기준·구간 샘플 4개, 첨부 이미지 10개를 빠짐없이 준비하는 검사가 통과했다. 영상 스틸은 FFmpeg 한 번으로 추출하며 이미지 최대 크기는 640×640이다. manifest에 모델 호출·외부 전송 없음과 자동 전사 미연결을 명시한다.

앞선 그림 앵커 단계의 PC 재검증은 35초 원본을 가져와 12초 유지·컷·2배속 후 10초/300프레임으로 렌더했다. 그림 75→75, 135→삭제, 285→225를 확인했고 대응 장면 픽셀 MAE는 0.49884/0.21050이었다. 명시적 빨강·파랑 도형 출력과 원본 SHA256 보존을 확인했다. 그 검사 당시 엔진 해시는 `d290d5d433b15d7894d180be64e301eae165d9ec170072a1a26df90493cd74a9`이며 전체 관련 코드 해시는 보고서에 있다. 이는 아래의 광범위 성능 벤치마크를 재실행한 결과가 아니다.

## 그림 기록과 키보드 이동 최적화

방향키를 길게 누르는 동작은 keydown마다 현재 도형을 갱신하되 keyup·포커스 이탈·창 비활성화에서 한 기록으로 확정한다. 전체 그림의 JSON 직렬화를 없애고 변경된 도형만 새 불변 값으로 보존한다. 같은 좌표를 쓰는 스타일 변경은 좌표 배열을 공유한다. Tab 포커스도 도구 활성 영역에 반영하며 진행 중인 드래그는 방향키 입력을 소비해 포인터 위치가 키 이동을 덮지 않게 한다. 이 입력 연결은 소스 검토·빌드 수준이고 브라우저 이벤트 검증은 남아 있다.

30개 펜×각 2,000점에 70회 동일 이동을 적용했다. warmup 2회 뒤 5회를 측정했고 두 경로의 최종 좌표가 매회 같음을 검사했다.

| 순수 상태 처리 | 이전 키 이동 경로 재현 | 새 그룹 기록 |
|---|---:|---:|
| 이동 1회 중앙값 | 6.089ms | 0.124ms |
| 이동 1회 p95 | 6.780ms | 0.166ms |
| 70회 묶음 중앙값 | 430.09ms | 9.09ms |
| 남은 기록 snapshot | 51 | 2 |
| 남은 고유 좌표 객체 | 160,000 | 62,000 |
| 시작 위치 복원 | 50단계 한도로 20회 이동이 남음 | undo 1회로 복원 |

전체 앱 버전 두 개를 실행한 비교가 아니라 이전 함수 경로를 재현한 Node.js CPU 측정이다. 객체 수는 할당 바이트·최대 메모리 사용량이 아니며 브라우저 입력 지연·페인트·FPS도 측정하지 않았다. [재현 스크립트](../scripts/benchmark-drawing-history.mjs), [수치·코드 해시](../storage/qa/drawing-history/report.json)를 보관한다.

PC 영상 검사도 새 기록 코어를 통과했다. 스타일 변경 뒤 70회 이동을 한 단계로 묶고 초안 기록을 다시 열어 undo→redo→undo→스타일 undo를 실행했다. 복원된 도형을 컷·배속과 함께 실제 영상에 넣어 빨강/파랑 픽셀, 대응 장면, 300프레임 출력, 원본 SHA256 보존을 확인했다. [실렌더 기록](../storage/qa/drawing-history/real-media/report.json)과 [출력 영상](../storage/qa/drawing-history/real-media/edited.mp4)은 그림 상태가 출력으로 이어지는 증거이며 실제 카드 클릭의 증거는 아니다.

## PC 실제 영상

지정된 기존 작업 폴더에서 영상 419개를 조사했다. 35초 본편과 서로 다른 코덱·프레임률의 원본을 선택했다. 테스트는 원본을 직접 입력하고, 개인 파일을 외부 AI로 전송하지 않았다. 원본 5개의 SHA256, 파일 크기, 수정 시각은 모두 유지됐다.

| 샘플 | 입력 | 출력 | FFmpeg 시간 | 최대 RSS |
|---|---|---|---:|---:|
| 음성 있는 본편 | 1080p / 30fps / 35초 | 30.5초 / 915f | 3.14초 | 617.8MiB |
| 무음 본편 | 1080p / 30fps / 35초 | 30.5초 / 915f | 2.84초 | 631.3MiB |
| HEVC 무음 | 1080p / 24fps / 14.04초 | 11.63초 / 349f | 2.94초 | 653.2MiB |
| H.264 무음 | 1080p / 25fps / 14.08초 | 11.67초 / 350f | 3.04초 | 603.7MiB |
| 타임스탬프 경계 | 720p / 24fps / 6.959초 | 5.27초 / 158f | 0.90초 | 295.4MiB |
| 세로 파생 | 608×1080 / 35초 | 30.5초 / 915f | 1.25초 | 243.2MiB |
| 4K 파생 | 3840×2160 / 6초 | 1080p / 4.5초 / 135f | 0.75초 | 857.6MiB |
| 회전 파생 | 90° display matrix / 6.07초 | 608×1080 / 4.57초 / 137f | 0.34초 | 309.6MiB |
| VFR 파생 | 평균 1200/59fps / 5.9초 | 30fps / 4.43초 / 133f | 0.47초 | 590.1MiB |

35초 본편은 전체를 읽어 컷·2배속·한국어 자막·PNG 합성을 적용했다. 테스트용 짧은 구간만 잘라 성공으로 계산하지 않았다. 세로·4K·회전·VFR 촬영 원본은 조사 폴더에 없어 기존 실제 영상의 파생 파일로 확인했다. 이를 실제 4K 촬영 원본 검증이라고 주장하지 않는다.

무음 입력 4종의 출력 PCM RMS는 모두 0이다. 검사 중 발견한 DC 오프셋은 float 오디오 형식으로 통일해 수정했다. 영상·음성 시작점과 길이는 검사했으며, 사람의 입 모양과 음성 싱크를 직접 판정하지는 않았다.

이 수치는 해당 PC의 특정 샘플 측정이다. 35초 음성 본편은 변경 전 2.56초에서 최종 3.14초로 측정되어, 모든 렌더가 빨라졌다고 결론 내리지 않는다. 확실한 개선은 오버레이로 인한 분할·입력 수와 메모리 감소다. 브라우저 드로잉 FPS나 입력 지연을 이 수치로 대신하지 않는다.

## 적용된 자막·그래픽 수정과 제거

현재 버전의 불변 snapshot을 레이어 목록으로 읽는다. legacy op는 기존 ID를 layer ID로 사용하며, 수정된 그래픽도 같은 layer ID와 새 op ID를 가진다. 수정·제거는 제안 상태로 저장되고 별도 승인을 거쳐 다음 버전에 반영된다. 교체는 기존 순서를 유지하며, 제거 op는 결과 snapshot에서 제외되지만 `appliedOpIds`에 실행 기록이 남는다. 이전 버전 영상과 snapshot을 덮어쓰지 않는다.

- 자동 검사: snapshot 6개, native 2개, 기존 API에 추가한 레이어 시나리오 1개. 오래된 대상·중복 대상·숨은 구간·잘못된 입력·이미지 역할·렌더 중 제거 수정 잠금·미승인 실행 거절을 확인했다.
- PC 검사: 35초 원본의 첫 6초, 180프레임을 원본·삽입·교체/제거·옛 버전 분기로 렌더했다. 픽셀 조건 14개 통과, 원본·기존 MP4·부모 snapshot 불변. 텍스트 색 변경은 별도 native 자막 검사로 확인했다.
- 타이밍: 기존 `[30,150)` 구간의 시작 전·시작·끝 직전·배타적 끝을 확인했다. 노출 구간 변경 기능의 증거가 아니다.
- 로컬 묶음: 원문 그림과 현재 수정안을 구분하고 대상 레이어의 불변 op·현재 제안·원본 구간을 함께 담는다. 자료 준비 중 해당 수정안을 잠근다. 외부 전송은 없다.
- 화면: 원본 장면 위의 독립 도형 편집창, 숫자 region·색·삽입 이미지 변경, 제거 확인을 연결했다. 메인 초안의 프레임을 유지하고 이미지 교체안을 기존 이미지 위에 중복 표시하지 않는다. 실제 클릭·드래그·포커스 검증은 남아 있다.

## 시간별 피드백 전달 프로토타입

현재 기본 흐름은 현재 시점/선택 구간, 직접 쓴 장면 설명과 피드백, 그림·참고·음성, 저장, 피드백 내보내기다. 작성창 진입은 재생을 멈추고 현재 media 시간을 읽는다. 음성은 녹음 시점의 구간과 그림을 유지한다. 이것은 소스·빌드 확인이며 실제 입력 포커스 검증은 남아 있다.

내보내기는 MD·JSON·장면 스틸·그림 표시·참고 이미지·오디오를 ZIP으로 묶는다. 원본·편집 영상 파일은 제외하며 외부 모델을 호출하지 않는다. API는 자료 생성 시작 당시 내용을 고정하고, 동시 동일 요청을 합치며, 같은 완료 자료를 다시 사용한다. 공유 첨부와 같은 장면은 한 번만 준비한다. 음성으로 올린 MP4도 영상 트랙을 제거한 오디오만 포함하는지 확인했다.

PC 35초 원본을 사용한 독립 검사에서 피드백 3개, 장면 12개, 그림 표시 3개, 공유 참고 이미지 1개를 확인했다. 작성 75→현재 45, 편집본 작성 75→현재 75, 삭제된 작성 45→현재 없음의 관계를 MD·JSON과 대조했다. 압축 해제 후 모든 자료의 상대 경로와 해시, 빨강·파랑·노랑 그림 픽셀을 검사했다. 원본·기존 버전·입력 상태는 유지됐다. 자동 장면 인식의 증거가 아니며 장면 설명은 검사 입력으로 직접 작성했다.

## 남은 화면 검증

레이어 수정·제거 요청, 모달에서 초안으로 복귀, 카드 필터 유지와 새 도구의 드래그·8방향 크기 조절·펜 입력·되돌리기와 이미지 이동을 실제 브라우저에서 확인해야 한다. 기존 요청의 현재 버전 투영, 삭제 카드, 분리 구간 선택, 범위 밖 그림 기준 안내, 초안 복귀와 미저장 보완 이어쓰기도 확인한다. 1280×800과 넓은 데스크톱 창에서 툴바, 비교 화면, 요청 패널 스크롤을 확인하고 도형 30개가 있는 상태의 입력 지연을 측정한다. 현재 브라우저 도구는 사용자의 허용 답변 및 설정 변경 뒤에도 `127.0.0.1:4317`에 대한 저장된 차단 사유를 반환했다. 이 항목은 통과 처리하지 않았다. 모바일 검증은 후속이다.


## 선택 영역과 화면 이동 중 드래그 보강

2026년 10월 14일 후속 감사에서 확인한 두 결함을 수정했다.

- 화살표 머리는 그림으로만 표시되고 클릭 대상은 14px 축선뿐이었다. 같은 화살촉 좌표의 투명 선택 polygon을 추가했다. 굵은 선과 펜은 실제 표시 굵기 이상, 최소 14px의 선택 폭을 사용한다. 둥근 선 끝·모서리와 한 점의 중심도 선택 영역에 포함한다.
- 드래그 시작 시 캔버스 위치를 캐시하므로 작업 화면을 스크롤하거나 창 크기를 바꾸면 이전 위치로 계산될 수 있었다. 캔버스 뷰포트 변경, 창 크기 변경, 캔버스를 포함한 조상의 스크롤에서 진행 중 제스처를 취소한다. 다른 패널의 스크롤은 영향을 주지 않으며 pointercancel/lostpointercapture는 활성 포인터 ID일 때만 처리한다. 포인터 이동마다 레이아웃을 다시 읽지 않는다.

`tests/overlay-hit-area.test.mjs`의 2개 검사는 실제 React 컴포넌트를 서버에서 SVG로 출력해 화살촉 polygon, 선 굵기와 화면 배율, 점 중심의 선택 영역을 검사한다. 화면 폭 400·1000·1600px, 선 굵기 0.25·3·20·64 범위의 해당 조합을 다룬다. 전체 166개 검사와 빌드가 통과했다. 브라우저에서 클릭 이벤트가 전달되는지나 30개 도형의 입력 지연을 측정한 결과는 아니다.
