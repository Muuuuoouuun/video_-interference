# AI 영상 편집 요청 앱 기획서

Oct 14, 2026 · @MOON

## 핵심 컨셉

**한 줄 정의: 영상 위에 "여기 이렇게 고쳐줘"를 남기면, AI가 그걸 편집 명령으로 바꿔 실행하고 새 버전을 돌려주는 앱.** Frame.io가 "사람 편집자에게 피드백 주는 도구"라면, 이 앱은 "AI 편집자에게 일 시키는 도구"다.

핵심은 코멘트를 그냥 텍스트로 두지 않고 **구조화된 편집 지시(EditOp)** 로 바꾸는 것이다. 사람은 Frame.io처럼 자유롭게 말하고 그리되, 그 뒤에서 AI가 `시간 범위 + 화면 영역 + 작업 종류 + 파라미터`로 번역한다. 사람이 그 번역을 확인하면 렌더러가 실행한다.

세 가지 원칙으로 설계한다.

1. **리뷰는 Frame.io처럼 익숙하게** — 타임스탬프 코멘트, 구간 지정, 화면 위 드로잉, 스레드 답글.
2. **실행 전 반드시 확인** — AI가 해석한 결과를 카드로 보여주고 승인한 것만 렌더.
3. **원본은 절대 안 건드림** — 매 버전은 원본 + 누적된 편집 지시 목록으로 처음부터 다시 렌더. 재인코딩 화질 손실도 없고 되돌리기도 쉽다.

## Frame.io에서 가져올 것 / 버릴 것 / 더할 것

Frame.io의 리뷰 UX는 거의 그대로 가져오고, "사람 편집자" 전제의 협업 기능은 뒤로 미룬다. 새로 더하는 건 전부 "AI가 실행한다"는 축이다.

| 기능 | Frame.io | 이 앱 | 우선순위 |
| --- | --- | --- | --- |
| 타임스탬프 코멘트 | 프레임 단위 코멘트 | 그대로 차용 — 코멘트 = 편집 요청의 단위 | P0 |
| 구간(범위) 코멘트 | 인/아웃 지정 후 코멘트 | 그대로 차용 — 컷·배속·자막의 범위가 됨 | P0 |
| 화면 드로잉 | 펜, 화살표, 사각형, 선 | 차용 + **영역 지정용**으로 확장 ("이 박스 안에 로고") | P0 |
| 스레드 답글 | 사람끼리 답글 | AI도 스레드에 답함 ("이 부분 맞나요?" 되묻기) | P1 |
| 버전 스택·비교 | v1/v2 나란히 비교 | 차용 — AI 렌더 결과가 새 버전으로 쌓임 | P1 |
| 첨부파일 | 코멘트에 파일 첨부 | **레퍼런스 이미지**로 확장 ("이 느낌으로") | P2 |
| 승인 상태 | Approved / Needs review | 코멘트별 상태: 접수 → 해석됨 → 승인 → 적용됨 | P1 |
| 공유 링크 | 외부 리뷰어 링크 | 클라이언트가 링크로 요청 남기기 | P3 |
| NLE 마커 내보내기 | Premiere·Resolve로 코멘트 전송 | FCPXML/EDL/OTIO로 내보내기 (사람이 마무리할 때) | P3 |
| 음성 코멘트 | 없음 | **새로 추가** — 녹음 → 자동 받아쓰기 → 지시로 변환 | P2 |
| AI 해석·실행 | 없음 | **새로 추가** — 이 앱의 본체 | P1 |
| Camera to Cloud, 팀 권한 관리 | 있음 | 버림 (개인/소규모 용도엔 과함) | — |

## 사용자 흐름

한 바퀴는 "요청 → 해석 → 승인 → 렌더 → 비교"이고, 비교 후 다시 요청을 남기며 버전이 쌓인다.

&#91;embedded content: 사용자 흐름 · 7단계, 되묻기 루프 1개\]

AI가 확신하지 못하면 렌더로 가지 않고 코멘트 스레드에 질문을 남긴다. 사람이 승인한 EditOp만 렌더되며, 매 렌더는 원본에서 처음부터 다시 만든다.

## 화면 구성

메인 화면은 하나다. Frame.io의 3단 레이아웃(버전 · 플레이어 · 코멘트)에 **AI 해석 카드**와 **"AI에게 맡기기" 버튼**을 더한 형태다.

&#91;embedded content: 메인 리뷰 화면 와이어프레임 · 5개 영역\]

코멘트를 남기면 바로 아래에 AI 해석 카드(EditOp 칩)가 붙고, 승인한 건수가 상단 버튼에 쌓인다. 단축키: Space 재생, ←/→ 한 프레임, I/O 구간 지정, C 코멘트, D 드로잉, V 음성 녹음.

## 요청 유형별 정의

모든 요청은 **입력 방식**(무엇으로 말하나)과 **작업 종류**(무엇을 시키나)의 조합이다. 입력은 4가지, 작업은 8가지로 시작한다.

**입력 방식**

- **텍스트 코멘트** — 한 지점(t) 또는 구간(in\~out)에 붙는다.
- **드로잉** — 그 프레임 위의 펜·박스·화살표. 좌표는 0\~1로 정규화해 저장 (플레이어 크기와 무관).
- **음성 코멘트** — 녹음 → 받아쓰기 → 텍스트 코멘트와 동일하게 처리. 원본 음성은 함께 보관.
- **레퍼런스 첨부** — 이미지·짧은 클립. "이 스타일로", "이 로고 넣어줘"의 재료.

**작업 종류 (EditOp type)**

| 작업 | 예시 요청 | 필요한 입력 | 실행 엔진 |
| --- | --- | --- | --- |
| `cut` 잘라내기 | "여기 3초 날려줘" | 구간 | FFmpeg |
| `trim` 인/아웃 | "영상 시작을 여기로" | 지점 | FFmpeg |
| `speed` 배속·빨리감기 | "이 구간 2배속" | 구간 + 배율 | FFmpeg (setpts/atempo) |
| `subtitle` 자막 | "여기 자막: 지금 바로 신청" / "전체 자막 달아줘" | 구간 + 문구 (또는 자동 받아쓰기) | Whisper + Remotion/ASS |
| `overlay` 그래픽·텍스트 | 박스 그리고 "여기 로고" | 구간 + 영역 + 레퍼런스 | Remotion |
| `zoom` 확대·크롭 | 원 그리고 "여기 줌인" | 구간 + 영역 | FFmpeg (crop/zoompan) |
| `audio` 음향 | "BGM 줄여줘", "여기 무음" | 구간 + 값 | FFmpeg (volume) |
| `note` 사람용 메모 | "색감은 나중에 내가 볼게" | 아무거나 | 실행 안 함 |

하나의 코멘트가 여러 EditOp로 쪼개질 수 있다. 예: "여기부터 2배속하고 자막으로 '빠르게 보기' 띄워줘" → `speed` + `subtitle` 두 개.

## 시스템 아키텍처

앱은 세 층으로 나뉠다. 사람이 말하는 **리뷰 레이어**, 그 말을 명령으로 바꾸는 **지시 레이어**, 명령을 실제 영상으로 만드는 **실행 레이어**.

&#91;embedded content: 시스템 아키텍처 · 3개 레이어, 9개 컴포넌트\]

AI가 보는 건 코멘트 텍스트만이 아니라 그 프레임 캡처에 드로잉을 겹친 이미지다. "여기"가 어디인지 글로 설명하지 않아도 되는 이유다. 각 레이어는 `packages/core`의 EditOp 스키마 하나로만 말한다.

## 데이터 모델과 EditOp 스키마

엔티티는 6개면 충분하다. 핵심은 **Comment(사람이 한 말)와 EditOp(AI가 번역한 명령)를 분리**하는 것 — 해석이 틀리면 EditOp만 고치면 된다.

| 엔티티 | 주요 필드 | 설명 |
| --- | --- | --- |
| Project | id, name, createdAt | 영상 묶음 |
| Asset | id, projectId, sourcePath, proxyPath, fps(분수), duration, width, height | 원본 영상 + 미리보기용 프록시 |
| Version | id, assetId, number, renderPath, opIds\[\], parentVersionId | v1 = 원본, v2부터 AI 렌더 결과 |
| Comment | id, versionId, frameIn, frameOut?, text, drawing?, voicePath?, transcript?, attachments\[\], status, parentId? | 사람(또는 AI)이 남긴 말. parentId로 스레드 |
| EditOp | id, commentId, type, frameIn, frameOut, region?, params, confidence, status | AI가 번역한 실행 단위 |
| RenderJob | id, versionId, status, progress, log | 렌더 작업 큐 |

**시간은 초가 아니라 프레임 번호로 저장한다.** 29.97fps 같은 분수 프레임레이트에서 초 단위는 반올림 오차로 한 프레임씩 밀린다.

EditOp 한 개의 모양 (예: 박스 그린 자리에 로고를 3초간):

```json
{
  "id": "op_8f2",
  "commentId": "c_41",
  "type": "overlay",
  "frameIn": 450,
  "frameOut": 540,
  "region": { "x": 0.72, "y": 0.06, "w": 0.22, "h": 0.12 },
  "params": {
    "kind": "image",
    "assetRef": "att_logo.png",
    "fadeIn": 6,
    "fadeOut": 6
  },
  "confidence": 0.86,
  "status": "proposed",
  "aiNote": "우측 상단 박스 영역에 첨부된 로고를 3초간 표시"
}
```

상태 흐름: `proposed`(AI 제안) → `approved`(사람 승인) → `applied`(렌더 반영) / `rejected`. 신뢰도가 낮으면(예: 0.6 미만) 자동으로 `needs_clarification`이 되고, AI가 해당 코멘트 스레드에 질문을 남긴다.

## 기술 스택과 웹 vs 로컬

**결론: "로컬에서 도는 웹앱"으로 시작한다.** Next.js로 만들어 브라우저에서 쓰되, 서버·렌더러·파일은 Mac Mini 같은 내 컴퓨터에서 돈다. 나중에 같은 코드를 클라우드에 올리면 그게 웹 버전이다.

이유는 세 가지다. 영상 파일이 수 GB라 업로드 비용이 크고, FFmpeg·Whisper는 로컬에서 그냥 돌며, Apple Silicon에서 받아쓰기·인코딩이 빠르다.

| 판단 기준 | 로컬 우선 | 클라우드 웹 |
| --- | --- | --- |
| 대용량 영상 | 디스크에서 바로 읽음 | 업로드 대기 + 저장 비용 |
| 렌더 비용 | 내 컴퓨터 | 서버 CPU 시간 과금 |
| 외부인 리뷰 링크 | 터널(Cloudflare Tunnel 등) 필요 | 기본 제공 |
| 개발 난이도 | 낮음 (인증·스토리지 생략) | 높음 |

**스택**

| 레이어 | 선택 | 메모 |
| --- | --- | --- |
| 프론트 | Next.js (App Router) + React + Tailwind |  |
| 플레이어 | HTML5 video + `requestVideoFrameCallback` | 프레임 정확도용. 프록시는 짧은 GOP로 인코딩해 탐색 정확도 확보 |
| 드로잉 | SVG 오버레이 + perfect-freehand | 벡터로 저장 → 다시 그리기·AI 전달 쉬움 |
| 타임라인 | 직접 구현 (canvas) + wavesurfer.js 파형 | 코멘트 마커·구간 바 표시 |
| DB | SQLite + Drizzle ORM | 파일 하나, 설치 없음 |
| 작업 큐 | 별도 Node 워커가 SQLite 폴링 | Redis 없이 시작 |
| 미디어 처리 | FFmpeg / ffprobe | 프록시·썸네일·파형·컷·배속·크롭 |
| 받아쓰기 | whisper.cpp (로컬) | 음성 코멘트 + 자동 자막 |
| 그래픽·자막 렌더 | Remotion | 회사 용도는 라이선스 조건 확인 필요 |
| AI 해석 | Claude API (비전) | 프레임 캡처 + 드로잉 합성 이미지 + 레퍼런스를 같이 보냄 |
| AI 실행 | Claude Agent SDK + 도구(ffmpeg, remotion, whisper) | EditOp 목록 → 타임라인 → 렌더 |

## 레포 폴더 구조

`video_-interference` 레포는 현재 비어 있다. 모노레포 하나에 웹앱·워커·공유 스키마를 둔다. EditOp 타입을 한 곳(`packages/core`)에서 정의해 웹·워커·AI 프롬프트가 같은 스키마를 쓰게 하는 게 핵심이다.

```
video_-interference/
├── apps/
│   ├── web/                  # Next.js — 리뷰 UI + API
│   │   ├── app/
│   │   │   ├── projects/[id]/review/   # 메인 리뷰 화면
│   │   │   └── api/                    # 업로드, 코멘트, 해석, 렌더 요청
│   │   └── components/
│   │       ├── player/        # 프레임 정확 플레이어
│   │       ├── draw/          # 드로잉 오버레이
│   │       ├── timeline/      # 마커·구간·파형
│   │       └── comments/      # 스레드 + AI 해석 카드
│   └── worker/               # 렌더·AI 작업 처리
│       ├── jobs/
│       │   ├── ingest.ts      # ffprobe, 프록시, 썸네일, 파형
│       │   ├── transcribe.ts  # whisper.cpp
│       │   ├── interpret.ts   # 코멘트 → EditOp (Claude)
│       │   └── render.ts      # EditOp[] → 새 버전
│       └── engines/
│           ├── ffmpeg/        # cut, trim, speed, zoom, audio
│           └── remotion/      # subtitle, overlay
├── packages/
│   ├── core/                 # EditOp·Comment 타입 + zod 스키마
│   ├── db/                   # Drizzle 스키마, SQLite
│   └── prompts/              # AI 해석 프롬프트 + 예시
└── storage/                  # (gitignore) 원본, 프록시, 렌더 결과
```

순서는 "리뷰 툴 먼저, AI는 그 위에"다. P0만 끝내도 혼자 쓰는 Frame.io 대체제로 쓸모가 있고, P1이 이 앱의 본체다.

다이아몬드는 다음 단계로 넘어가기 전 통과 기준이다. P1은 작업 종류를 `cut`·`trim`·`speed` 세 개로 좁혀, FFmpeg만으로 끝까지 한 바퀴 도는 걸 먼저 본다.

## 리스크와 결정할 것

가장 큰 리스크는 기술이 아니라 **AI가 요청을 잘못 알아듣는 것**이다. 그래서 해석 확인 단계와 되묻기 기능을 P1부터 넣는다.

| 리스크 | 영향 | 대응 |
| --- | --- | --- |
| AI 오해석 ("여기"가 어디인지) | 엉뚱한 편집 → 신뢰 하락 | 프레임 캡처 + 드로잉 합성 이미지를 같이 전달, 신뢰도 낮으면 스레드에서 되묻기 |
| 브라우저 탐색이 프레임 정확하지 않음 | 코멘트 위치가 1\~2프레임 밀림 | 짧은 GOP 프록시 + 프레임 번호 저장 + 화면에 프레임 넘버 표시 |
| 편집끼리 충돌 (컷한 구간에 자막 요청) | 렌더 실패 또는 이상한 결과 | 렌더 전 충돌 검사, 컷 이후 타임코드 자동 재계산 |
| 렌더 시간 | 긴 영상이면 매번 수 분 | 먼저 저해상도 미리보기, 승인 후 고화질 렌더 |
| 그래픽 품질 | AI가 만든 오버레이가 촌스러움 | 자막·로우서드 템플릿 몇 개를 미리 만들고 AI는 고르기만 |

**결정할 것**

- [ ] 주 사용자: 나 혼자 쓰는 도구인가, 클라이언트·팀원에게 링크로 요청받는 도구인가 (P3 공유 기능 우선순위가 바뀜)
- [ ] 다룰 영상: 강의·인터뷰처럼 말 중심인가, 광고·쇼츠처럼 그래픽 중심인가 (자막 vs 그래픽 엔진 우선순위)
- [ ] 최종 출력: AI가 완성본까지 만드는가, 프리미어·다빈치로 넘길 초벌까지인가
- [ ] 영상 길이 상한: 10분 이하로 시작할지 (렌더·받아쓰기 시간 기준)
