# Vertex 이미지 생성 CLI

이 명령은 텍스트 설명만으로 이미지 생성을 요청한다. 기본 실행은 외부 통신과 파일 쓰기가 없는 미리보기이며 앱 화면이나 기존 피드백 저장·내보내기에는 연결되지 않는다. 개인 영상·이미지·음성은 읽거나 전송하지 않는다.

```sh
# 외부 호출 없이 설정 검사
printf '%s' '노란 풍선 한 개' | node scripts/vertex-image.mjs --project PROJECT_ID

# 인증과 요금·크레딧 적용을 확인한 뒤 명시적인 호출 1회
printf '%s' '노란 풍선 한 개' | node scripts/vertex-image.mjs --project PROJECT_ID --live --request-id NEW_UUID_V4
```

실제 호출에는 로컬 Application Default Credentials(ADC)와 해당 프로젝트의 Vertex AI 사용 권한, 결제 및 모델 접근이 필요하다. `gcloud auth login`과 ADC는 별도 설정이다. 공식 Google 인증 라이브러리가 ADC를 찾아 액세스 토큰을 갱신한다. 자격 증명은 코드나 결과물에 저장하지 않는다. 프로젝트·모델 권한과 과금 크레딧 적용은 실제로 검증하지 않았다.

`--live`는 입력한 설명을 Google에 전송하며 비용이 발생할 수 있다. 프로젝트 ID를 명시하고, 작업마다 새 UUID v4를 지정한다. Google 모델은 `gemini-3.1-flash-lite-image`와 `global` 위치로 고정했다. 설명은 2,000자 이하이며 영상·참조 이미지·음성 전송 기능은 없다.

비용을 제한하기 위해 후보 하나, 출력 최대 2,048토큰, 단일 요청, 자동 재시도 없음으로 설정하고 한 장을 생성하도록 지시한다. **후보 한 개가 이미지 한 장이나 요금 상한을 보장하지 않는다.** 공급자가 이미지 여러 장을 생성하면 응답을 오류 처리하나, 이미 발생한 요금까지 막을 수 없다. 토큰 제한은 이미지 생성 실패나 잘린 응답을 일으킬 수 있다. 월 예산과 크레딧 적용 여부도 이 CLI가 강제로 보장하지 않는다.

결과는 `storage/vertex-images/요청ID/image.png` 또는 `image.jpg`에 저장한다. 사용한 요청 ID는 저장 디렉터리로 남으며, 실패·타임아웃·저장 실패 이후에도 같은 ID로 다시 호출하지 않는다. 전송 이후의 오류는 과금 여부가 불확실할 수 있으므로 청구 내역을 확인한 뒤 다음 작업을 판단한다. 새 ID를 지정해 다시 실행하면 별도 유료 요청이 된다. `VI_STORAGE_ROOT`가 명시된 경우 해당 경로 아래 같은 구조를 사용한다. 출력 폴더의 심볼릭 링크는 거부한다.

생성 결과는 기존 프로젝트, 첨부, 렌더 및 승인 상태에 자동으로 들어가지 않는다. CLI의 공개 합성 문구 이미지 생성 1회는 실계정으로 확인했으며, 해당 호출의 크레딧 차감 여부는 확인하지 않았다.

## 앱 화면에서 이미지 생성

앱 화면의 **AI 이미지 생성**은 기본 비활성이다. `npm run dev`와 `npm run worker`는 Git에 포함되지 않는 `.env.vertex.local`을 서버에서만 읽는다. 프로젝트 ID와 비밀이 아닌 활성화 설정만 넣고, 인증 정보는 Google ADC에서 관리한다. 같은 이름의 셸 환경 변수가 있으면 파일 값보다 우선한다. 기존 `.env.local`은 서버에서 자동으로 읽지 않는다.

```sh
VI_VERTEX_GENERATION_ENABLED=1 VERTEX_PROJECT_ID=PROJECT_ID npm run dev
```

설명은 2,000자 이하다. 한 번에 하나의 생성 작업을 진행하고, 프로젝트에 자동 삽입하지 않는다. 앱이 종료되면 완료된 이미지가 온전히 저장되어 있는 경우 다시 확인해 보여 주며, 그 외에는 결과·과금 확인이 필요한 상태로 남긴다. 서버를 재시작하거나 화면을 다시 열어도 중단된 생성 요청을 자동으로 다시 보내지 않는다. 실제 앱에서의 유료 생성은 아직 검증하지 않았다.
