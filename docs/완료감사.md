# 완료 항목과 남은 완성 조건 감사

2026년 10월 15일 갱신 · 기준 작업 폴더 `/Volumes/OneTouch/video_interference` · 데스크톱 우선 · 1인용

최신 사용자 결정에 따라 현재 프로토타입은 **영상 파일 전달이 아닌, 시간별 장면 내용과 피드백 전달**에 집중한다. 기본 화면은 시점·구간 선택, 장면 설명과 피드백 저장, 그림·참고 자료, 내보내기로 구성했다. 기존 해석·승인·렌더는 선택적인 편집 기능 안에 보존했다. 자세한 범위는 [피드백 프로토타입](피드백프로토타입.md)이다. 아래의 전체 편집 제품 요구사항은 후속 제품 계획으로 유지하며 이번 프로토타입의 완료 조건과 구분한다. 모바일은 후속이다.

사용자는 요청을 먼저 저장하고 나중에 AI로 해석하는 흐름을 허용했다. 기본 앱은 로컬 자료 준비를 유지한다. 이후 사용자가 Gemini API 테스트를 지시하여 선택한 피드백·스틸을 읽는 별도 검증 경로를 추가했다. 저장·내보내기는 자동으로 외부 호출을 하지 않는다. 따라서 매번 즉시 해석하는 동작은 완료 조건이 아니다. 글·그림·음성·참고 자료를 보존하고 같은 요청에서 해석을 다시 시도할 수 있는지가 기준이다.

제품 우선순위는 **1 본질 → 2 편의성 → 3 사용성**이다. 이번 단계의 본질은 어떤 장면에 어떤 피드백을 남겼는지 보존하고 읽기 쉬운 자료로 전달하는 것이다. 편의성은 즉시 저장·보완·한 번에 내보내기, 사용성은 시점과 작성 상태를 분명하게 보여 주는 것이다. 자동 편집과 즉시 AI 호출을 기본 피드백 흐름의 선행 조건으로 두지 않는다.

**판정 기준**

- **입증됨**: 실행한 자동 검사나 실제 산출물 증거가 있다. 증거가 검사하지 않은 조건까지 확대하지 않는다.
- **약함**: 구현과 소스 검사는 있으나 실제 브라우저·실제 공급자·해당 미디어 조건의 통합 검증이 없다.
- **미완료**: 원래 기획의 완성 조건이 구현되지 않았거나 아직 통과하지 않았다.
- **진행 중**: 담당자가 구현·회귀 검증을 진행하고 있으며 통과 결과를 아직 반영하지 않았다.
- **명시적 후속**: 기획에서 첫 제품 뒤로 둔 기능이다. 완성 MVP의 필수 항목을 이 분류로 옮기지 않는다.

범위 기준은 [참고기획.txt](참고기획.txt), [초기기획.md](초기기획.md), [최종기획.md](최종기획.md), 최신 [제품원칙](제품원칙.md)이다. 최종 기획의 「이번 초안과 완성 MVP」는 현재 초안의 경계를 설명한다. 앞부분의 제품 원칙·시간 앵커·상태·레이어 요구사항은 완성 MVP의 기준으로 유지한다. 이후 구현 범위는 [README](../README.md), [오버레이 개발 기록](오버레이개발.md), 실제 소스와 함께 대조했다.

Gemini 별도 검증은 실제 호출 1회로 피드백 3개·이미지 16개를 분석했다. 관찰 장면·보완 의도·삭제 상태를 대조했고 원문과 시점은 그대로 유지했다. 모델이 시간 매핑을 직접 계산한 것은 아니다. 앱의 자동 해석·편집·음성 전사는 여전히 이 검증 범위에 포함하지 않는다. [실제 결과와 범위](Gemini테스트.md).

후속 코드 감사에서 드래그 중 화면 스크롤·크기 변경 시 좌표가 어긋나는 문제와 화살촉·굵은 선의 일부를 선택하지 못하는 문제를 발견해 수정했다. 캔버스 위치가 바뀌면 진행 중인 제스처를 취소하고, 취소 이벤트는 활성 포인터에만 적용한다. 선택 영역은 표시된 그림 전체를 포함하도록 보강했다. 펜 정점과 저장되는 그림 좌표 형식은 유지한다.

앞선 실행 앱 검사에서는 워커 정상 응답, 프로젝트 버전 2개·피드백 5개·휴지통 0개와 실행 중 렌더 0개를 확인했다. 검증용 API 테스트는 격리된 저장소를 사용한다. 브라우저 목록에서 기존 탭이 `data:` 연결 실패 페이지임을 확인했으나, 허용된 HTTP 주소를 내장 브라우저로 여는 작업도 **저장된 사이트 접근 차단**으로 거절됐다. 실제 데스크톱 클릭·드래그·입력 지연·마이크·복사/다운로드 증거가 없으므로 전체 완료로 판정하지 않는다. [이전 완료 감사 기록](../storage/qa/overlay-gesture/completion-audit.json)은 후속 수정 전 시점의 기록이다.

이번 PC 재검증은 35초 원본에서 12초를 유지하고 컷·2배속 및 두 장면의 명시적 도형 삽입으로 10초·300프레임을 만들었다. 그림 앵커 75→75, 135→삭제, 285→225와 실제 출력 픽셀을 확인했고 원본 SHA256을 보존했다. 보고서의 코드 해시를 현재 소스와 대조했다. 실행 앱 재시작 후 기존 요청 3개·버전 2개를 유지했고, 기존 요청의 자료 ZIP과 모든 파일을 내려받아 무결성을 검사했다. 외부 모델 호출·전송은 없었다.

그림 기록 최적화에서는 30펜×2,000점, 70회 연속 이동을 검사했다. [이전 키 이동 경로와 새 상태 코어 비교](../storage/qa/drawing-history/report.json)의 중앙값은 6.089→0.124ms/이동, p95는 6.780→0.166ms였다. 이는 순수 JavaScript 계산이며 실제 브라우저 입력·페인트 지연이 아니다. 새 그룹은 한 번의 undo로 전체 이동을 복원했다. [PC 재렌더](../storage/qa/drawing-history/real-media/report.json)는 기록 복구·undo/redo로 되돌린 도형의 위치·색상이 실제 출력에 보존되는지 확인했다. Tab 포커스 소유권과 드래그 중 방향키 충돌도 소스로 보완했으나 실제 입력 검수는 남긴다.

레이어 수정·제거의 [PC 검증](../storage/qa/layer-revisions/report.json)은 35초 원본 중 6초로 원본·삽입·수정·이전 버전 분기를 각각 만들었다. 14개 픽셀 조건에서 옛 그림 위치 복원, 삽입 이미지 제거, 새 위치·색, 기존 위쪽 그래픽 순서, `[30,150)` 반열림 구간 보존을 확인했다. source·이전 MP4·부모 스냅샷은 불변이었다. 자막 색상 교체는 별도 native 검사로 확인했다. 보고서 엔진·도형·resolver 해시는 현재 코드와 일치한다. 실행 워커를 재시작한 [읽기 검사](../storage/qa/layer-revisions/live-after.json)에서도 기존 버전 2개·댓글 3개와 원래 자막 레이어를 유지했다. UI 통합은 빌드·소스 검토 수준이고, 실제 도형 수정창 조작과 노출 구간 변경을 검증했다고 확대하지 않는다.

**증거의 시점과 해석**

[PC 최종 보고서](../storage/qa/real-media/after-final/report.json)는 실원본 5개·파생 4개·stress 4개, 실패 0이며 원본 해시를 보존한다. [baseline](../storage/qa/real-media/before-timed/report.json)과의 비교는 서로 다른 시간의 도형 30개를 61→1 시간축 구간으로 줄였고 같은 시간의 도형 30개를 30→1 PNG 입력으로 합쳤다. 30개 도형 중 펜 29개×1,000점의 래스터 준비는 86ms→캐시 2ms였다.

이 PC 보고서는 오버레이 최적화 단계의 엔진 스냅샷에서 측정했다. 이후 취소·입력 검증·A/V offset 보완이 진행됐으므로 현재 전체 코드와 동일 해시의 벤치마크라고 표현하지 않는다. 이후 동작의 근거는 해당 회귀 검사다. `/usr/bin/time -l`의 native FFmpeg 최대 RSS와 250ms 간격 sampled RSS는 별도 값이다. 일반적인 렌더 전체가 빨라졌다는 결론도 내리지 않는다.

[오버레이 검증 기록](오버레이검증.md)과 [실제 출력 프레임](../storage/qa/real-media/after-final/full35-caption-native.png), [드로잉 출력 프레임](../storage/qa/real-media/after-final/arrow-pen-rendered.png)은 미디어 출력 증거다. 새 브라우저 입력 동작의 증거로 사용하지 않는다. 저장 DB 집계는 지속 저장의 증거이며 실제 UI 재시작 절차를 대신하지 않는다. 실제 Claude 호출·자동 STT·사람의 입 모양에 대한 판정은 이 검사에 포함하지 않았다.

[현재 프로젝트 읽기 기록](../storage/qa/request-projection/live-readback.json)은 API의 저장 상태와 투영 계산을 대조한다. v1 514프레임·v2 454프레임에서 원본 범위 150–270→150–210, 270–360→210–300을 확인했다. 이것도 실제 브라우저 조작 증거는 아니다. 이번 투영 검사는 원본 PTS 인덱스나 VFR 원본 프레임과의 정밀 대응을 검증하지 않는다.

**현재 프로토타입에서 진행할 순서**

1. 시간·장면 내용·피드백·그림을 저장하고 문서와 묶음으로 전달하는 기본 흐름을 검수한다. 재생 중 입력창에 직접 들어가도 영상을 정지하고 현재 시간을 읽어 저장하도록 연결했다.
2. 작성 당시 스틸과 현재 버전 대응을 구분하고, 삭제된 장면·구간 밖 그림·원문과 보완 기록이 누락되지 않는지 검사한다.
3. 접근이 허용된 데스크톱 브라우저에서 시점/구간 전환, 초안 복귀, 녹음, 그림 이동·크기·되돌리기, 복사·다운로드를 확인한다. 현재의 저장된 접근 차단을 우회하지 않는다.
4. 실제 AI·음성 전사·자동 편집·PTS 정밀 앵커·버전별 적용 이력은 후속 편집 제품 계획으로 보존한다. 새 프로토타입의 기본 전달 흐름을 검수한 뒤 우선순위를 다시 정한다.

입증된 항목은 유지하고 실제 증거가 생길 때 해당 판정을 갱신한다. 프로토타입의 데이터·내보내기 검증과 실제 화면 조작 완료는 구분한다.

## 우측 댓글 중심 화면 개편

첨부 HTML의 통합 리뷰/큐 리스트 시안을 밝은 회색·흰 패널·파란 강조색으로 반영했다. 프로젝트 패널은 기본 접힘, 댓글 패널은 기본 펼침이며 양쪽을 접어도 컴포넌트와 초안을 유지한다. 앱 시작 시 첫 댓글·예시 구간을 자동 선택하지 않는다. 한 시점으로 시작하며 구간 지정/I/O 이후에만 IN/OUT과 반복 재생이 나타나고, 구간 해제는 반복도 함께 끈다.

댓글 작성창은 항상 보이며 첨부·음성·장면 설명·저장 후 해석은 추가 옵션, 그림의 색·굵기·채움은 그림 스타일, 기존 구간·마크업 재사용은 별도 접기 영역으로 옮겼다. 녹음 종료·실패 재시도와 이미 첨부한 자료는 추가 옵션을 접어도 보인다. 명령 해석·비교·렌더는 더 보기의 편집 기능에서 켠다.

정적 출력과 전체 회귀·빌드는 통과했지만 이번 라이트 테마의 실제 배치·드래그·키보드 포커스·스크롤은 화면 검수하지 못했다. 도구의 사이트 접근 제한을 우회하지 않았으며 일반 Chrome에서 해당 사이트를 조작한 것으로 기록하지 않는다.

## AI·도구용 전달 형식 v2

2026-10-15 사용자 결정: 작업물을 AI와 다른 코드 형태로 빠르게 받아 해석하는 것이 핵심이며, 영상·이미지는 필요할 때만 본다. 전달 자료를 **글 먼저 → 피드백별 한 장 요약 → 개별 스틸** 순서로 바꿨다. 형식은 [AI·도구용 전달 형식](AI전달형식.md), 규격은 [JSON Schema](../schema/feedback-handoff.schema.json)다. 이 검증은 리눅스 클라우드 환경(FFmpeg 6, Chromium 헤드리스)에서 실행했다.

| 조건 | 판정 | 근거와 남은 확인 |
|---|---|---|
| 그림 좌표를 위치 문장으로 | 계산·native 입증 | 박스·원·선·화살표·펜(점·선·둘러싼 표시) 단위 검사. 내보내기 문서·JSONL·VTT에 같은 문장이 들어가는지 확인. 정확한 좌표는 manifest에 그대로 둔다. |
| 피드백별 한 장 요약, 그림 표시 JPEG | native 입증 | 칸 수=스틸 수, 첫 칸=기준 프레임, 그림 칸 표시, 이미지 크기를 검사. 시각 라벨은 장면 아래 띠에 두어 장면·그림을 가리지 않는다. 그림 표시 스틸은 검증 영상 기준 PNG 약 200KB → JPEG 약 40KB. |
| 영상 개요와 컷 구간 | native 입증 / 실제 영상 정확도 약함 | 한 번의 디코딩으로 12칸 흐름 이미지와 컷 목록을 만들고 버전 파일별로 캐시한다. 합성 영상의 빨강→파랑 경계(30·60·150프레임)를 정확히 찾았다. 실제 촬영·화면 녹화 영상의 컷 감지 품질은 검증하지 않았고 `estimated: true`로 표시한다. |
| JSONL·VTT 출력 | native·API 입증 | 첫 줄 묶음 정보와 피드백 줄 수·번호·원문·보완, VTT 구간·부분 생존 구간·한 시점 2초 표시와 영상 끝 제한, 삭제 피드백의 NOTE 보존, 특수 문자 이스케이프를 검사했다. |
| 전달 형식 규격 | 입증됨 | 피드백 내보내기, 편집 기능 AI용 자료, CLI 결과를 모두 같은 JSON Schema로 검증한다. AI용 자료는 기존 최상위 필드를 유지하고 `feedback[0]`에 공용 항목을 더했다. |
| CLI 내보내기 | 입증됨 | 앱 DB 파일 해시가 실행 전후 같고, 같은 내용은 캐시를 재사용하며, 삭제한 피드백은 빠진다. 잘못된 버전·형식·저장 폴더는 오류로 끝난다. |
| 로컬 받아쓰기 | API 입증 / 실제 인식 품질 미검증 | 가짜 whisper.cpp로 16kHz WAV 변환·플래그·결과 저장·내보내기 반영·미설정 시 409를 검사했다. 실제 whisper.cpp 바이너리로 같은 플래그와 JSON 출력 경로를 확인했으나, 모델 다운로드가 막혀 무작위 가중치 테스트 모델만 사용했다. 한국어 인식 품질은 사용자 PC에서 확인해야 한다. |
| Gemini 한 장 요약 모드 | 로컬 준비 입증 / 실제 호출 미실행 | 검증용 합성 영상의 피드백 3개 묶음에서 이미지 16장(912KB) → 4장(236KB). 실제 Gemini 호출과 토큰 수, 작은 칸으로 인한 판독 손실은 측정하지 않았다. |
| AI 관찰 붙이기 | CLI 입증 | `observations.json`을 붙이면 모델 결과로 따로 표시하고, 이후 바뀐 피드백은 `stale`, 없는 ID는 개수로 남긴다. 사용자 장면 설명을 대체하지 않는다. |
| 받아쓰기 버튼·결과, 내보내기 링크 화면 | 헤드리스 화면 입증 | 빌드한 앱을 Chromium 헤드리스로 열어 받아쓰기 버튼 → 결과 표시, 내보내기 대화상자의 JSONL·VTT 링크와 실제 JSONL 응답을 확인했다. 콘솔 오류 0. macOS 실제 브라우저 조작은 아니다. |
